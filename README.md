# Fukuruma

**▶ Play in your browser: <https://makesgamessteve-hash.github.io/fukuruma/>**

A space exploration game about wonder and scale: modern lighting, effects and animation, seen
through a retro low-resolution filter. You command a moon-sized Jump Ship that carries space
stations, which carry flying mountains, which carry walking cities, which carry giant walkers, which
carry you, in an environmental exosuit. Every doll in the chain can be deployed, boarded and
explored. Every planet is worth going down to, and any planet can kill you.

| Doll | Size |
|------|------|
| Jump Ship | 144 km |
| Space Station | ≈ 31 km |
| Continental Explorer | ≈ 6.7 km |
| Land Explorer | 1.44 km |
| Exploration Walker | 72 m |
| Exosuit | 3.6 m |

## Status

Milestones M0 (build, test and deployment pipeline), M1 (engine core), M2 (reference frames and scale), M3 (galaxy
and star systems) and M4 (planets from space) are done. The
sandbox: the Exosuit, a 3.6 m skinned mech, walks and runs over a test range at dusk and sends out sensor scans. Under the hood: a
deterministic 60 Hz simulation, input for keyboard, gamepad and touch, a deferred PBR renderer at a low internal
resolution (cascaded shadows, ambient occlusion, bloom, eye adaptation, temporal anti-aliasing), four graphics detail
levels, glTF models and textures, GPU skinning with blend trees, particles, camera shake and rumble, 3D sound with
music generated by ElevenLabs, saves, and hot reload of scripts, shaders and assets. Since M2 the sandbox is seen through the Commander's eyes from inside the Exosuit, with a survey drone's outside view
for orientation; a frame tree in double precision, depth slices and scaled space hold a 1 m cube, a 144 km hull, a
planet and a star in one scene; bodies move on Kepler orbits; and deterministic physics lets the suit climb low
steps, stop at walls and shove the crates. Since M3 the range stands on a world of a generated star system in a
generated galaxy: the real star lights it and sets, the sky shows the real neighbouring stars and the galactic band,
and the galaxy and system maps let you jump to other stars, each system with its own worlds and marvels. Since M4 every world has a
surface from noise graphs (continents, ridges, dunes, craters, ice, banded giants, rings, clouds) streamed as
cube-sphere chunks, air that scatters its star's light into its own skies and sunsets, and stars that glow in their
own colours; binaries light worlds twice and pulsars sweep their beams. M5 (seamless surfaces) is in progress.

## Controls (sandbox)

| | Keyboard | Gamepad | Touch |
|---|---|---|---|
| Look around | mouse (click into the browser window first) | right stick | drag on the right half of the screen |
| Walk the Exosuit (towards where you look) | W A S D or the arrow keys | left stick | stick on the left half of the screen |
| Sprint | Shift | A | RUN button |
| Sensor scan | E | X | SCAN button |
| Outside view (survey drone, for looking only) | V | Back | VIEW button |
| Galaxy and system maps (Tab switches, ← → choose, Enter jumps) | M | Y (X switches) | MAP button |
| Settings (graphics, comfort, audio) | Escape | Start | MENU button |
| Quick save / quick load | F5 / F9 | in the settings menu | in the settings menu |
| In the menu: choose, change, close | ↑ / ↓, ← / →, Escape (or the mouse) | d-pad or stick, A, B | tap a row, tap left or right of a value |

The settings are saved (in the browser in its local storage). The graphics start on a level that suits the
device: Low on phones and software renderers, Medium in desktop browsers, High elsewhere. Camera shake,
light flashes, rumble and head bob can be turned down in the menu, which also sets the field of view and the
vignette while turning.

## Technology

- Core engine in **C11** with **SDL3** and **OpenGL** (3.3 core, ES 3.0, WebGL 2)
- Game logic in **Lua 5.4**; scripts, shaders and assets live in `data/` beside the binary, mods in `mods/`
- Targets: Windows, Linux, macOS, Web (Emscripten, with touch controls on mobile) and WebXR
- Spec-driven development with [OpenSpec](https://github.com/Fission-AI/OpenSpec); agent rules from
  [ponytail](https://github.com/DietrichGebert/ponytail) in [AGENTS.md](AGENTS.md)
- Unit tests with at least 95% line coverage, plus automated game tests

## Building

Requirements: CMake 3.24+, Ninja, a C11 compiler, Python 3 (tests). SDL3 is downloaded by CMake.
On Linux, SDL3 also needs the X11/Wayland development packages (Ubuntu:
`libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxi-dev libxss-dev libxfixes-dev libxtst-dev
libxkbcommon-dev libwayland-dev wayland-protocols libegl-dev`).

```bash
cmake --preset linux-debug && cmake --build --preset linux-debug
```

```bash
build/linux-debug/fukuruma
```

Other presets: `windows-msvc`, `macos`, `web` (needs the Emscripten SDK in `$EMSDK`), `linux-coverage`,
`linux-asan`. The executable reads everything from the `data/` folder next to it; edit a script and
rebuild (which copies `data/`) or edit the copy in the build folder and restart.

## Testing

```bash
ctest --preset linux-debug
```

```bash
cmake --preset linux-coverage && cmake --build --preset linux-coverage --target coverage
```

```bash
cd tests/web && npm install && npx playwright install chromium && node smoke.mjs ../../build/web
```

- `fukuruma --test tests/lua` runs the Lua unit tests; `--coverage` records Lua coverage with luacov.
- `fukuruma --headless --scenario tests/game/boot.lua` runs a game-test scenario offscreen and compares its
  screenshots with `tests/golden/`; `--update-golden` rewrites the reference images; `--no-render` runs
  without a GPU (screenshots are skipped).
- The coverage target fails below 95% line coverage for the C engine or the Lua scripts.
